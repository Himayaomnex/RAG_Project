# Executive Strategic Decisions — Operational Skill Specification

## 1. Skill Purpose & Scope
This skill defines a single, repeatable executive task: **synthesizing major strategic decisions and technical trade-offs** agreed upon in meeting dialogues, strictly separating established facts from agent recommendations.

---

## 2. Input Specification (What the LLM Receives)
1. **Target Entity / Scope**: Full cohort or specific trainee / system component.
2. **Raw Transcript Evidence Chunks**: `<turn date="..." doc="..." page="..." speaker="..."> spoken text </turn>`

---

## 3. Output Specification (What the LLM Must Produce)
A single, valid Markdown Pipe Table with this exact schema:

```markdown
| Owner | Decision Type (Fact vs Recommendation) | Synthesized Decision & Strategy (70%) | Trade-off Given Up | Citation (30% Proof) |
| :--- | :--- | :--- | :--- | :--- |
```

### Invariant Rules:
- **Decision Type**:
  - `Fact (Decided in Meeting)`: Explicitly agreed upon by mentor/team during dialogue.
  - `Recommendation (Agent)`: Strategic proposal generated by the agent based on evidence.
- **Trade-off Given Up**: State what alternative was sacrificed (e.g. *"Gave up simplicity for lower latency"*, *"Sacrificed initial speed for exhaustive recall"*).
- **The 70/30 Rule**: 70% articulate strategic explanation; 30% clean citation `[Date, Page — Speaker]`.

---

## 4. Step-by-Step Execution Workflow (For Raw LLM)
1. **Scan for Decision Turns**: Look for phrases like *"we will do this"*, *"don't use X, use Y"*, *"let's decide on"*, *"I recommend"*.
2. **Classify Fact vs Recommendation**: Determine if the turn records a finalized team decision or an open option.
3. **Isolate the Technical Trade-off**: Identify the downside or alternative given up.
4. **Render Markdown Table**: Populate the schema with clean citation references.
